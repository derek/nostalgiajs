The post that made "JavaScript fatigue" a catchphrase was mostly a list of fixes for React's tooling, and seven months later the React team shipped a tool that matched part of the list and thanked the post's author.

Saul: "How's it going?"
Me: "Fatigued."
Saul: "Family?"
Me: "No, JavaScript."

Eric Clemmons opened a post called "Javascript Fatigue" with that exchange, from a coffee with a friend a few days earlier, and it was on Hacker News on December 27, 2015. The line after the exchange takes the title back: "More accurately, I meant React and the JavaScript ecosystem that comes with it."

Clemmons was chief technology officer of HigherEducation.com at the time, and the grievance was a working one. The team had started three new projects that quarter, and each had required its own decisions about tooling.

A React Hello World in late 2015

React asked for a build step sooner than most libraries did. Its components were written in JSX, which no browser runs, so in practice a React project started with a compiler, and the compiler was Babel. On October 29, 2015 Babel 6 came out under a note from James Kyle calling it "a very disruptive major". Babel had decided to be a platform for tools and no longer just a transpiler, so a fresh install now transformed nothing until you picked plugins or a preset such as es2015 or react. Clemmons was writing two months into that.

Babel was one tool of several. A project also wanted a bundler, a linter and a development server, and the description Dan Abramov gave on the React blog the following July is fair to all of them: "Many of those tools are plugin platforms and don't directly acknowledge each other's existence. They leave it up to the users to wire them together."

On December 26, 2015 Christopher Chedeau, who writes as Vjeux, published a challenge, prompted by what it calls a big discussion on Twitter the day before about how hard it was to start a JavaScript project. Chedeau's best setup ever, the challenge says, dated from the age of 14: connect to a server with WinSCP, make a file called test.php, and type:

<?php echo 'Hello World';

Save, wait half a second for the upload, click the file in a browser. Chedeau wanted that for JavaScript and React: nothing to set up for a new project, and a single file ("No package.json, no .babelrc, no Procfile").

What Clemmons asked for

The diagnosis in Clemmons's post comes under the heading "Too Many Tools." and fits in a sentence:

Ultimately, the problem is that by choosing React (and inherently JSX), you've unwittingly opted into a confusing nest of build tools, boilerplate, linters, & time-sinks to deal with before you ever get to create anything.

Then Clemmons turns down the usual remedy. Teams coped by copying a boilerplate project or running a generator such as Yeoman, and Clemmons, who had written a generator, argued that neither held up across many projects. Generated code is a copy. When the setup improves, the improvement has to be carried by hand into every project made from it, because the common code "is not abstracted into an independently updatable dependency."

The rest is a list of things to build instead. Library authors should offer an opinionated, "author-endorsed" wrapper for the 90 percent of cases that Clemmons supposed were alike. Tools should ship presets, as Babel had just done. File and folder naming conventions should stand in for configuration. And there should be tooling that gets a prototype running first and leaves the decisions for later, which is where Clemmons cites Chedeau's challenge and names five projects already trying, nwb among them.

The forecast is cheerful. Clemmons wrote that the pendulum had swung from restrictive frameworks to modular libraries buried in boilerplate, and would soon settle in between. The last line is "Here's to an exciting 2016! :)". Read from the second heading on, the post is a specification with a complaint on top.

The title leaves the post behind

Hacker News took the post twice inside a day. The first submission used its title. Whoever made the second put the missing word back, as "React/JavaScript fatigue", and that thread ran to 183 comments.

The first objection I can find is to the name. A React developer who posts as chantastic reacted to the post, Clemmons asked what was meant, and on December 29 chantastic answered in a gist: "Articles titled like yours have a tendency to take a life of their own. The bulk of my reaction was to the title itself and the resulting conversation." The gist agrees that building React apps was painful and that abstractions could help newcomers. It disputes that this was the state of JavaScript at large, that it needed solving yet, and that React apps were alike enough for one wrapper to serve them.

Clemmons replied underneath the same day, restating the post in a sentence. Two days after publishing, the author was explaining what it had said.

By January 18, 2016 Ben Halpern was warning against letting the phrase become a buzzword. Halpern's own definition was the narrow one: the setup that frameworks, "namely ReactJs", demanded before a first screen.

I think the phrase was always going to get away, for plain reasons. A title is the one part of a post that circulates without a click, and this title said JavaScript where the body said React. It also arrived when anyone who had upgraded Babel, chosen a bundler or inherited somebody else's Gulp file had a fatigue of their own to file under it. Nothing in the two words told them that the author's was more specific, or that it came with a plan.

Create React App, version 0.1.0

On July 22, 2016 Abramov announced Create React App, a command-line tool that sets up a React project with no configuration. Abramov had written it with Christopher Chedeau, the author of the Christmas challenge. The two had agreed over Messenger to spend a hackathon week on it, after Abramov came back from EmberCamp impressed by the command-line tool that Ember had.

The people who made React had been spared the problem, and I think that is one reason the problem lasted. The announcement says Facebook's practice was to release only code it used itself, and that inside Facebook the linting, transpiling and packaging were done by remote development servers that product engineers never had to configure. Chedeau had told Abramov that several "React CLI" projects had started inside Facebook and failed. Abramov called shipping this one an exception to the practice, and called the tool an experiment: "only time will tell if it becomes a popular way of creating and building React apps, or fades into obscurity."

A new app's package.json looked like this:

{
  "name": "hello-world",
  "dependencies": {
    "react": "^15.2.1",
    "react-dom": "^15.2.1"
  },
  "devDependencies": {
    "react-scripts": "0.1.0"
  },
  "scripts": {
    "start": "react-scripts start",
    "build": "react-scripts build",
    "eject": "react-scripts eject"
  }
}

The project has no webpack config, no .babelrc and no lint file. All of that lives inside react-scripts, which is why Abramov can promise that "you can update a single dependency to get them all." Clemmons's objection to generators had its answer: the common code was now an independently updatable dependency. The price was in the same announcement. The build settings were fixed, testing was missing, and the way out was eject, which copies the whole configuration into your project and so turns it back into a boilerplate.

The announcement's "Backstory" section says where the diagnosis came from. "Eric Clemmons called this phenomenon the 'JavaScript Fatigue'", Abramov wrote, and quoted the sentence about the confusing nest of build tools. The closing paragraph thanks six people for "early feedback, ideas, and contributions". One is Clemmons. Another is Jonny Buchanan, the name the npm registry gives for the author of nwb. Abramov says the tool was meant to fix the problem Clemmons had named. Abramov does not say it was built in answer to Clemmons's post, and I won't either.

Aguinaga's dialogue, October 2016

On October 3, 2016, ten weeks after Create React App and six months after left-pad vanished from npm for an afternoon, Jose Aguinaga published "How it feels to learn JavaScript in 2016" and submitted it to Hacker News.

The piece is a conversation. Someone who has not built for the web in a few years needs a page that fetches user activity from a REST endpoint and shows it in a filterable table, and proposes jQuery. The other speaker, who prefers the title "Front End engineer", says no one uses jQuery anymore and prescribes React, which comes with React DOM and JSX, which call for Babel, which wants a bundler, and on through Browserify, Webpack, SystemJS, TypeScript, Flow, Fetch and a roll-call of template engines, before conceding that a page which only displays data never needed React. The newcomer gives up on the web altogether: "The JavaScript community is insane if it thinks anyone can keep up with this." Hackernoon's copy has been read more than 700,000 times, by its own counter.

Set beside Clemmons's post, the complaint has changed shape. Clemmons objected to the decisions a React project demanded before work could start, which a good default can remove. Aguinaga's newcomer objects to how much there is to know and how fast it is replaced, across the whole language, which no default removes. The word "fatigue" appears nowhere in the dialogue, and in the two Hacker News threads about it, some 420 comments, I count it once, from a commenter claiming "JavaScript Fatigue Fatigue". That the dialogue is what the phrase now calls to mind is my own reading of how it is remembered.

Create React App appears nowhere in the dialogue either. It came up in the comments, where one reader said there was no need to know the toolchains "if you just use create-react-app" and another answered much as chantastic had in December: "Yes, you DO need to know the toolchain."

The form was second-hand, and said so. A note at the top credits "It's the future" from CircleCI's blog, Paul Biggar's parody of the container ecosystem, which Hacker News picked up on June 9, 2015. Ten days later Biggar published "It really is the future". Many of those who reacted had taken the parody as accurate and not as satire, Biggar wrote, and they were wrong: containers were how applications were going to be built. Readers had also compared it to the state of front-end development, six months before Clemmons's coffee with Saul.

After Create React App

Create React App became a category of tool and then was retired. On February 14, 2025 the React blog published "Sunsetting Create React App", by Matt Carroll and Ricky Hanlon, deprecating it for new apps. Their history of 2016 is Clemmons's argument in the past tense: people had wired the tools together by hand, the community's boilerplates "were difficult to update", and a single recommended configuration had solved that, in a model they say a whole category of tools now follows. The tool was being retired because it had no active maintainers (the latest react-scripts, 5.0.1, dates from April 2022) and because frameworks now covered the same ground. Abramov had offered two outcomes, popular or obscure, and the experiment delivered both, in that order.

A short reply to the satire came from the library that became htmx. Two days after Aguinaga's piece, Carson Gross posted a version of the dialogue on the blog of intercooler.js, a library built on jQuery that makes AJAX requests from HTML attributes. It reuses Aguinaga's opening lines and changes the expert, who answers "Nope. I'm just an old web dev guy" and recommends returning bits of HTML from the server. The whole conversation is over in eleven exchanges.

The takeaway

"JavaScript fatigue" began as a specific complaint with a remedy attached. A React project made you assemble a build before you could write a line, and copies of that build could not be upgraded. For the build tools, the remedy Clemmons asked for, an opinionated default endorsed by the library's authors and updated as one dependency, is what Create React App turned out to be. The phrase did not stay with React. As I read it, it became the name for something no package can fix: the sense that there is more of the ecosystem than one person can follow. The piece that best expresses that sense never uses the word.

Clemmons's post is on the author's own site, with the coffee at the top and "Here's to an exciting 2016! :)" at the bottom. By the post's own measure the year delivered, since a default of the kind it asked for shipped in July. What people kept was Clemmons's first word to Saul.
