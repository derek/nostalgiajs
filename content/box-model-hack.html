Two of the four declarations in the Box Model Hack are about the voice of a speech synthesiser, and the person who wrote them had been development lead on Microsoft's own browser engine for the Mac.

div.content {
  width:400px;
  voice-family: "\"}\"";
  voice-family:inherit;
  width:300px;
}

The rule is the working part of a page on Tantek Çelik's site, finished in March 2001. A browser that parses CSS properly sets a width of 400 pixels, gives voice-family (a property CSS2 defined for aural style sheets) a peculiar string, sets it back to inherit, and then replaces the width with 300. Internet Explorer 5 and 5.5 for Windows take the brace inside the string for the end of the rule and never see the last line, so they keep 400. The two numbers produce the same box. The box on the page has 20 pixels of border and 30 of padding on each side, and the Windows browser counted those as part of the width where every other browser added them on.

Çelik was development lead for Tasman, the engine inside Internet Explorer 5 for the Macintosh, from 1998 to 2000, and in March 2001 was still at Microsoft, leading work on a later Tasman for its TV products group; the titles are from Çelik's own résumé. Internet Explorer on the Mac already measured a box the way the specification said. The hack was for the other Internet Explorer.

One company, two box models

CSS1, a W3C Recommendation since December 1996, defines the width of an element as "the width of the content", with padding, border and margin added around it. Declare a box 300 pixels wide with the hack page's border and padding and it occupies 400. Internet Explorer 5 for Windows drew it 300 across and took the border and padding out of the inside, leaving 200 for the content. Add up your column widths for one kind of browser and the layout was a hundred pixels out in the other.

The plainest statement of the difference came from inside Microsoft. In October 1999 a poster on the W3C's www-style list supposed that box-sizing, a property in the CSS3 drafts, had been invented because of Internet Explorer. Çelik answered that it hadn't: it came from the user-interface draft, for buttons and other controls whose borders belong to the operating system, and the credit was Peter Linss's. One of its values, border-box, did happen to describe how Internet Explorer for Windows treated width and height by default. Internet Explorer for the Mac, Çelik went on, followed CSS1, and then came a stage direction:

(ducks while angry web authors throw overripe fruit at the implementor for being inconsistent from WinIE)

The message is signed from Tasman Development, Microsoft Corporation. Microsoft was shipping both box models at once, one per operating system, and the implementor of the conforming one was the one bracing for fruit. Who decided that the Windows browser should measure that way, and why, I could not find anyone at Microsoft saying. The same message notes that border-box also describes how HTML's own WIDTH and HEIGHT attributes were popularly implemented, which may be the reason; that is my inference, not Microsoft's account.

The doctype switch in the Mac browser

A browser maker that corrects its box model breaks every page whose numbers were chosen to suit the old one. The way out came from Todd Fahrner, whose suggestion to Mozilla's layout list is preserved in the W3C's history of the idea: ship two rendering systems, keep the old one for old content, and "Pay attention to the DOCTYPE."

Çelik built that switch into Internet Explorer 5 for the Mac, which shipped in March 2000. With no doctype, or an old one, it imitated Internet Explorer for Windows, box model included; with a strict one it followed CSS1. Çelik's notes from August 1999 say the imitation's rules "are not for the sake of authors. The quirky behaviors are there for the sake of users", whose old pages should go on looking as their authors meant.

Three versions of one hack

In February 2001 Jeffrey Zeldman was rebuilding A List Apart without layout tables and writing up the experience, in an article dated 16 February that now reads as Zeldman rewrote it on 7 April. The first attempt looked right in Internet Explorer 5 for Windows and grew scrollbars in Internet Explorer 5 for the Mac, Netscape 6 and Opera 5. Zeldman's diagnosis was that those three were correct and the fault was shared: "I didn't understand the CSS box model correctly (and neither did IE5/Win)." A deliberately wrong width of 67% made the Windows browser draw the column at roughly the 52% it should have been, which took 14 hours to work out. Then a second rule gave the true figure to better browsers through a CSS2 child selector, which the Windows browser did not understand and skipped:

body>#content {
 width: 52%;
    padding: 35px 5% 100px 10%;
 }

The article credits the trick to "Anonymous Donor A", one of two unnamed CSS experts. Çelik's log entry of March 2006, written from an email archive, says the suggestion was Çelik's. In print it lasted a day. On 17 February Anil Dash pointed out what A List Apart's home page looked like in a browser that had the box model right but had never heard of the child selector: it read the deliberately wrong width, believed it and went no further. The entry adds that Internet Explorer 4.5 for the Mac, "a browser I had worked on", was another such browser, and then one word: "Oops."

The second version swapped the selector for a parsing bug in Internet Explorer 5.0 for Windows, and held for two weeks. On Saturday 3 March Fahrner found that Internet Explorer 5.5 had fixed the bug. The third version was done before midnight.

Çelik went looking where parsing bugs were already laid out in rows: section 7.1 of the W3C's CSS1 test suite, a page of deliberately strange style rules that checks whether a browser throws away what it doesn't understand and carries on. The résumé says Tasman was the first engine to pass that suite. With Fahrner's help Çelik found one test that upset both Windows versions:

P.twentyb {rotation-code: "\"}\""; color: green;}

There is no property called rotation-code. The test page says the paragraph "should be green, because only the first declaration is invalid": a correct parser discards the nonsense, string and all, and reads on to the colour. Internet Explorer 5, in the words of a comment in the hack's style sheet, "prematurely closes the rule".

Çelik also wanted the hack to be valid CSS, so the invented property gave way to "an abandoned CSS2 property which accepted arbitrary string values", as a later entry puts it. At 11pm Pacific time, having tested in five browsers and expecting Internet Explorer 6 to fix both the parsing bug and the box model, Çelik mailed the result to Fahrner and Zeldman. The page adds one more rule after the hack, html>body .content {width:300px;}, for browsers that understand CSS2 selectors but share the Windows parsing bug: the "be nice to Opera 5" rule. The child selector that failed as the hack came back as its safety net.

Internet Explorer 6 fixes the box, if asked

Later that month Microsoft released a public preview of Internet Explorer 6, and with it an MSDN article by Lance Silver with a section headed "Fix the Box Instead of Thinking Outside It". Earlier versions, Silver wrote, did not comply with the CSS1 box model. The new one measured width the CSS1 way on one condition: the page had to begin with a !DOCTYPE that switched on what Silver called standards-compliant mode. Every other page got the old arithmetic, and the article offers that as the good news: "you're unlikely to experience any significant compatibility problems with applications you developed for earlier versions of Internet Explorer."

Silver's table of which doctypes flip the switch is close to the rules Çelik had written down for the Mac. No doctype: off. HTML 4.0 Strict: on. An unrecognised doctype: on. HTML 4.0 Transitional: on if the declaration includes the DTD's URL, off if it doesn't. Çelik wrote in 2003 that Internet Explorer 6 "largely adopted" the Mac switch. Çelik was not a neutral witness, but the rules bear that out.

Silver was writing for people with applications to keep running. The article tells anyone who built one for an earlier version to make sure its doctype does not switch the new mode on, and warns against the new mode for "content that is fixed in nature, such as content that is stored on a CD", since rendering there might change in later versions. The mode named for the standard came without a guarantee, and the advice for anything meant to last was to stay out of it.

The Box Model Hack spreads

The hack travelled further than a page of test boxes had any right to. By February 2004 Anne van Kesteren could write that "(almost) every commercial site has at least one CSS hack, a box model hack". The same piece carries the catch: the hack's numbers only came out right if Internet Explorer 6 was in standards mode.

That made the doctype a trap. An addendum to Çelik's page dated 4 April 2002 records that Prerit Bhakta had noticed a page beginning with <?xml version="1.0"?> put Internet Explorer 6 back on the old box model, and advises leaving the line out. In Çelik's Mac browser the same line had meant strict. An MSDN article on Internet Explorer 7 by Markus Mielke and Dave Massy later called the behaviour a bug, introduced it with "Sadly", and said version 7 had fixed it.

Çelik was uneasy about what the hack started. In November 2005 an entry titled "Pandora's Box (Model) of CSS Hacks And Other Good Intentions" traced a line from it to a generalised version that hid whole style sheets from Internet Explorer 5, and from there to hacks for nearly every browser, many of them breaking rules Çelik had kept in mind in 2001 and never written down. One rule was that a hack should be valid. Another was that it should be ugly, the ugliness serving as "a reminder to dispose of them when no longer necessary". By that standard the line with the string in it is a complete success.

Where the two box models went

The Windows model became a CSS property. box-sizing, the property from the 1999 thread, lets an author ask for either arithmetic one element at a time. Zeldman had conceded the appeal in 2001: "The way IE5/Win works seems preferable in many ways, but it's wrong." In 2012 Paul Irish recommended applying border-box to every element on a page, on the grounds that a box declared 200 pixels wide ought to be 200 pixels wide. MDN's page on the property now says browsers apply it by default to tables, buttons and several form controls. The initial value is content-box, so CSS1 kept the default and the Windows arithmetic got the recommendation.

The switch outlived the browsers it was built for. Henri Sivonen's reference on doctypes and browser modes describes the quirks mode of Internet Explorer 6 to 9 as "effectively frozen IE 5.5", and says versions 10 and 11 kept that imitation beside a newer quirks mode built to match other browsers. MDN says that the only purpose of <!doctype html> today is to switch quirks mode off, and that no browser ever used a doctype for anything except choosing a rendering mode.

Microsoft's advice and Çelik's ended up nearly word for word the same. Internet Explorer 7 changed strict mode and fixed parser bugs that later hacks depended on, pages broke, and the Mielke and Massy article is the guide to the damage. Its first guideline for anyone who must use a filter reads: "Target ONLY 'older than current' (frozen or abandoned) versions of browsers." Çelik's entry of November 2005 has "Target ONLY older/frozen/abandoned versions". The article adds that filters aimed only at Internet Explorer 5.5 and earlier are relatively safe, which is a fair description of the Box Model Hack. The hacks that broke were aimed at the browser of the day, and what Microsoft did about that in Internet Explorer 8 is the story of a meta tag.

The takeaway

The Box Model Hack was a Microsoft engineer's patch for a Microsoft browser: the former lead of the Mac browser's engine making the Windows browser's boxes come out like the Mac's, with a bug the W3C's test suite had been written to catch. I read it as a colleague's fix, and a careful one: valid, tested in five browsers and aimed at browsers that were about to be replaced. Microsoft's own fix is the part that lasted. Internet Explorer 6 put a correct box beside the old one and let the first line of the page choose between them, so that nothing old broke and nothing old had to be fixed. The web kept both: every browser has a quirks mode, and the measurement Zeldman called preferable but wrong is one declaration away.

Under the test box on Çelik's page are two bars for comparison, a red one 300 pixels long and a blue one 400. The text says the box should be as wide as the blue bar.
