The tracker that got JavaScript an off switch

In February 1996 a web page could follow you around the web and report each address you visited to a stranger, and the one browser that ran such pages had no setting to stop them.

Remember: We're watching...

That is the last line of a page titled "Real Time History Tracking", written by John Robert LoVerso on February 22, 1996. When I fetched it from LoVerso's own site, it sat much as it was left. Its headline reads "JavaScript in Netscape 2.0 shouldn't let me do this, But it does". A few lines above the sign-off is a link labelled "Invoke the tracker", and further up is a sample of what the tracker collected:

Wed Feb 21 23:34:07 EST 1996
REMOTE_ADDR = xxx.xxx.xx.x
REMOTE_HOST = xxxxxxxxx.com
QUERY_STRING = result=3= http://www.yahoo.com/Business_and_Economy/Companies/Apparel/Lingerie/
HTTP_USER_AGENT = Mozilla/2.0 (X11; I; SunOS 5.4 sun4m)  via proxy gateway  CERN-HTTPD/3.0 libwww/2.17

The page explains that this entry "was from a test a friend did for me". So at 11:34 on a Wednesday night, a friend on a Sun workstation opened a Yahoo category page, and a server at LoVerso's office wrote the address down. The friend knew. The point of the page was that the next person would not.

I came to this page expecting JavaScript's first security hole. It wasn't the first, and LoVerso said so at the time. What it was is odder: the report that, as far as I can tell, did most to get JavaScript an off switch, argued over in public for three weeks by a commuter and the language's author.

JavaScript, fresh out of beta

Netscape and Sun announced JavaScript on December 4, 1995. The language was already in people's hands by then under its earlier name, LiveScript, in the public betas of Navigator 2.0. The finished Navigator 2.0 came out around the start of February 1996; Keith Dawson's newsletter Tasty Bits from the Technology Front, dated February 10, reported it "was released last week on all platforms".

Almost nobody could say what the new thing was. The name suggested a small Java, and Sun's Java was the most carefully examined language of the moment. Dawson's issue of February 19 told readers that if they were confused about the difference "you are not alone", and passed on a report that Netscape already regretted the name. It then reprinted a comparison table adapted from Netscape's own tutorial. The two columns differed on every row but the last:

          JavaScript                            Java
 Secure. Cannot write to hard disk.   Secure. Cannot write to hard disk.

The betas had already put that row in doubt. Netscape ran a contest it called the Bugs Bounty, paying $1,000 for a security bug, and JavaScript kept winning it. In beta 2, Scott Weston found a way for a script to send a transcript of a visitor's whole session back to a page's owner; Dawson called the demonstration "massively scary" and noted it was fixed in beta 3. In January, John Tennyson reported a cluster of bugs with a similar effect, including one that let a script list the directories on your disk. Both were awarded the bounty.

Then 2.0 shipped, and on February 13 LoVerso, a researcher at the OSF Research Institute in Cambridge, told Netscape that Tennyson's directory lister still worked in the finished product. His adapted copy of the exploit survives, credited "Originally By" Tennyson. The trick was to submit a form to a file: address in a new window and then read that window's links. The window was asked to be as small as a window can be:

winopts =
  "toolbar=no,location=no,directories=no,status=no,menubar=no,scrollbars=no," +
  "resizable=no,copyhistory=yes," +
  "width=0,height=0"
;

LoVerso's train ride home

On Wednesday, February 21, LoVerso hit a bug by accident. He had a page whose onload handler put up an alert and then called history.back(), and a user at OSF who visited it found the handler would not go away. LoVerso posted to comp.lang.javascript that morning under the subject "Serious Security Bug":

I have seen a case where JavaScript imported from one page is being executed by the Navigator for EVERY subsequent page it renders.

He couldn't make it happen on demand, which makes for a poor exploit. That afternoon, in Netscape's own newsgroup, the language's author Brendan Eich answered a thread titled "Finding out a user's history?". LoVerso later quoted the reply on the tracker page: the copyhistory option had been disabled in beta 6 "to prevent your session history, with potentially secret keys or other URL query strings, from being stolen by malicious hidden scripts."

LoVerso went home by commuter rail. Somewhere on that ride he worked out that he didn't need the unreliable bug at all. A script that stays in memory after you leave its page is a defect. A script that sits in its own window is just a window, and Navigator 2.0 let a script in one window ask another window where it was.

The tracker's own source is the one piece I could not recover. It was served by a program on an OSF machine, and that address no longer answers. What survives is LoVerso's description, which is exact enough. His script opened a second, "(mostly) hidden" window and stayed there. Then, in his words, "it wakes up every second and sees what page you are viewing", and when the address changed it requested a CGI script on his server with the new address in the query string. That request is the log entry near the top of this essay. The page says the demonstration's windows were left large enough to see, and that a real attack could ask for width=1,height=1.

The timestamp on that sample entry is 11:34 the same night. By my reading of the dates, the idea went from a train seat to a working spy in an evening.

A browser with no JavaScript switch

On Friday morning LoVerso sent the story to the RISKS Digest, Peter G. Neumann's moderated forum on the hazards of computers. It ran in volume 17, issue 79 as "Netscape Navigator 2.0 exposes user's browsing history", between a year-2000 bug and a reply from Sun about Java security.

The post is careful about its claims. LoVerso called his tracker "the third (or fourth?) way to steal private data from a user via JavaScript", and claimed only one thing as new: it worked in real time, on the finished 2.0, for as long as its window lived. Addresses carried secrets then as now, so anything a site put in a URL, a password or a session key, went into the log with the rest. He noted that Navigator opened Netscape's own home page at startup, that the page was full of JavaScript, and that a log of where people went next was worth a great deal to an advertiser.

Then came the paragraph that mattered most:

As it stands, with Netscape 2.0 you cannot disable JavaScript. You can disable Java.

LoVerso thought that the wrong way round. Java's design had been pored over by thousands of people. Nobody outside Netscape had seen JavaScript's source, and its specification was whatever Navigator did. You could read any one script with View Source, but nothing told you a page had a script in it, and by the time you looked it had already run.

So people improvised. LoVerso's tracker page asked readers to write to Netscape and request a button. One correspondent in Netscape's developer newsgroup, whose name the surviving copy doesn't give, went further and reported having edited the program itself: "we've patched the binary to not recognize the SCRIPT tag, the onLoad function, and the 'livescript:' URL scheme". On March 7, according to Dawson, the security office of the Naval Research Laboratory advised U.S. military personnel not to use Netscape 2.0 until the problems were fixed. Two days before that, by LoVerso's own tally of the coverage, the story had been on the front page of the San Jose Mercury News.

Netscape's bounty, and Eich's word "minor"

Netscape had in fact answered before RISKS ran the story, and the answer was friendly. Dawson's account, which LoVerso says he was allowed to check before it went out, has Netscape telling LoVerso on Thursday night, the day the tracker page is dated and the evening before the RISKS submission, that he had won a $1,000 bounty. The money was slower. When the San Jose Mercury News reported on March 5 that he had received it, LoVerso noted: "This is not (yet) the case. I've been told I will receive such a prize..." His list of reported problems now records the prize as awarded, and adds: "They also sent me a Mozilla mug."

The second answer came a week later and was neither. On February 29 Eich replied at length to the newsgroup correspondent with the patched binary. The message survives because a subscriber named Alex Kremer reposted it to a JavaScript mailing list the next day under the subject "*THIS* is the official word", although Eich's last lines say it is his opinion and not the company's. Eich ranked the holes:

I consider the directory listing and mail spamming/address-stealing holes serious; the history tracker less so.

The tracker was minor, Eich wrote, "because it is far from invisible" on every system he had tried. That was fair as far as it went: the demonstration was built to be seen. The same message conceded the larger point in one clause. A special release, 2.01, was about to replace 2.0, and it would fix the directory and mail bugs, "plus adding a Preference to disable JavaScript".

The rest of the message is the best record I've found of how JavaScript's security was meant to work, and why the two of them talked past each other. I see three forces at work, two of them in this message.

The first is that the feature and the hole were the same thing. Frames arrived in the same Navigator release as scripting, and a script that could not look into another frame or window could not do much with either. Eich's rule was that a script and the documents it examined "must come from the same server". The directory lister got through because that check had a bug. The tracker, as LoVerso described it, read another window's address with no bug involved. That is why LoVerso complained on his page of press clippings that reporters kept missing the point: the tracker used "a designed in feature of the language".

The second is an honest disagreement about method. The correspondent wanted a written security model, something with the "sense of formalism" Java had. Eich answered that formalism had not saved Java, which had just needed a patch for a hole found by students at Princeton, and that he put more faith in code review and in paying people to publish their attacks. He also sketched what he wanted to build next: "taint" bits on private data, an idea borrowed from Perl, so that a script could read your history but could not send it anywhere.

The third is that Netscape could hardly ship JavaScript switched off, as LoVerso had suggested, because its own site depended on the language. When the off switch arrived, TidBITS noted that with JavaScript disabled, pages that leaned on it, Netscape's included, might load worse than they did in browsers that had never heard of it.

By then the argument had left the mailing lists. That Mercury News story ran on the front page, and the clippings page keeps score of what followed. CMP's NetGuide got LoVerso's name wrong. Educom's Edupage newsletter misread the Mercury News and, in his words, "has just gotten Tennyson a job at OSF", which took three days to correct. PC Week started its story on page 1 on March 11 and printed his web address without his name. Again and again he read that Netscape's patch for the Java hole had fixed JavaScript's bugs. The stories led with stolen e-mail and directory listings, and the tracking that he called "my real discovery" was "often downplayed or left out". The first article he judged to "get everything right" was James Staten's in MacWeek on March 13, nearly three weeks after the RISKS post.

Navigator 2.01, broken in four days

Navigator 2.01 fixed the tracker and added the switch, and four days later LoVerso had the tracker running again. The release began appearing on Netscape's FTP server on March 14, three weeks to the day after the date on the tracker page. Frank Hecker, who worked in pre-sales technical support at Netscape, told the JavaScript list that morning, with a postscript saying the note was not an official announcement. A bulletin from the Energy Department's incident team, reprinted in RISKS, listed five JavaScript problems, two already fixed in 2.0 and the rest fixed by 2.01. The fifth was the logging of every address a browser visited. Whatever Eich thought of the tracker on February 29, the patch covered it.

And there was the switch. Padgett Peterson told RISKS readers where to find it: "you can turn JavaScript off (Options/Security)." LoVerso added an update dated 3/14 to the tracker page, saying the hole was fixed.

The next update on the page is dated 3/18 and says there is a new way that works in 2.01. This time he did use the stuck onload bug from the morning of February 21, because he had found a dependable way to set it off: have the script throw up an unexpected Save File dialog and wait for the user to press Cancel. As he told the www-security list, "you'd press CANCEL, too, if that happened to you!" By March 22 he had two more attacks on 2.01, a rebuilt directory lister and a way to make any form button upload a file from your disk.

What he did next is the part I didn't expect from the person whose page signs off "We're watching". He gave the two worse exploits to Netscape and to nobody else, and held them back for six weeks, partly because they were nasty and partly, he wrote, "because Netscape asked me to". He linked them only on May 1, once Navigator 2.02 was out and had fixed all three. And his March 22 note ends by pointing readers at the thing he had asked for in February: anyone on 2.01 could avoid all three attacks by switching JavaScript off.

Where the tracker's fixes went

The same-server check got a name and became the rule everything else rests on. Netscape's later Client-Side JavaScript Guide opens its security chapter with the same origin policy, and explains it in terms of this exact winter: the restriction "prevents scripts from fetching private information such as directory structures or user session history". By my reading those are Tennyson's bug, then Weston's and LoVerso's. Eich has since described how it came about in two words. The abstract of a talk he gave in 2012, "The Same-Origin Saga", opens: "I created what became known as the browser 'Same-Origin Policy' (SOP) under duress for Netscape 2, 3, and 4 in the mid-nineties." The rule needed many more patches: the W3C's security FAQ, in an entry dated August 1997, describes scripts in invisible windows recording every page a user visits in Navigator 3, Communicator 4 and Internet Explorer 3 and 4, with variants that "reappear at almost monthly intervals".

Eich's taint bits shipped, were withdrawn and left a fossil. The same guide records that data tainting arrived in JavaScript 1.1, the version in Navigator 3.0, where a user had to set an environment variable called NS_ENABLE_TAINT to turn it on, and that "it was removed in JavaScript 1.2". The method scripts used to ask about it outlived the feature. The HTML Standard still specifies navigator.taintEnabled() for browsers in what it calls Gecko compatibility mode, in one sentence: "The taintEnabled() method must return false."

The off switch lasted seventeen years in plain sight. It moved from the Security preferences to a Languages tab in the previews of Navigator 3.0, and its descendant was still a checkbox in Firefox when Alex Limi, of Mozilla's Firefox UX team, filed a bug in March 2013 titled "Remove 'Enable JavaScript' checkbox from Prefs". Limi's essay on the subject argued that most sites that do more than display content now fail "in interesting & mysterious ways" without scripts, so that to ordinary users a browser with the box unticked simply looks broken. Firefox 23, released August 6, 2013, took the checkbox out and reset anyone who had used it to the default. The setting survived in about:config, for people who know to look there.

LoVerso stopped collecting bugs. His list of reported problems has a note that he is no longer gathering JavaScript bugs because his time is going to "other, more important pursuits", a 2002 postscript wondering what he might have found had he kept at it, and a complaint that the file upload bug never earned him a second prize: "I would have preferred another $1000".

The takeaway

The first public fight over the safety of the finished JavaScript was not about a crash or a virus. It was about whether a page you had left could keep watching you, and it was settled in three weeks by a patch, a prize and a preference. The patch tightened the same-server check that later got the name same origin policy. The prize was a thousand dollars and a mug. The preference was an admission that the only safe answer to "what can this script do?" was, for a while, "nothing, if you say so". Eich was right that the 1996 demonstration was easy to spot, and LoVerso was right that spotting it was not the user's job. The web that followed took LoVerso's fear seriously and his remedy less and less, until a browser could remove the switch on the grounds that nobody could afford to use it.

The tracker page is still up, with its dated updates and its 1996 log entry. The "Invoke the tracker" link points at port 8000 of a machine called freebase.osf.org, which did not answer when I tried it. Nothing is watching at that address now. The last line of the page hasn't been changed, and it has turned out to be a fair description of the web.

What I couldn't verify

  • The tracker's own source code is lost: it was served by a program on an OSF machine that no longer answers, so my account of how it worked comes from LoVerso's descriptions, and the statement that the 2.01 patch stopped one window reading another site's address is my reconstruction from them.
  • No source says the preference to disable JavaScript was added because of LoVerso's report. He asked for a button, an unnamed correspondent asked Eich for the same thing, and there was other pressure at the time, so "the report that did most to get JavaScript an off switch" is my reading.
  • The Thursday-night bounty call comes only from Keith Dawson's newsletter, which places it after the RISKS post, while the RISKS header is dated Friday morning; I followed the header. The Naval Research Laboratory advisory also rests on Dawson alone, and I could not find any of the 1996 press articles themselves, so the Mercury News front page and everything else I say about the coverage rest on LoVerso's own list of it.
  • I know Brendan Eich's message of February 29, 1996 only from Alex Kremer's repost to a mailing list the next day, and I could not open Netscape's own 2.01 release notes or security note, so Netscape's side rests on that repost, Frank Hecker's unofficial note, the CIAC bulletin and TidBITS.
  • Sources disagree on when Navigator 2.0 shipped: TBTF of February 10, 1996 says it was released the week before and LoVerso was testing it on February 13, while "JavaScript: The First 20 Years" gives March 1996. I followed the 1996 sources.
  • That the idea became working code in one evening is my inference from the timestamp on the sample log entry, and reading the same origin policy's later wording as a description of the Tennyson, Weston and LoVerso bugs is my own interpretation.
  • I know Eich's 2012 talk only from its abstract, as kept by a conference index, and have not seen the talk or its slides.
